# Project schema v2

TypeScript definitions and strict runtime validation live in packages/schema/index.ts. Parsing enforces a 1 MB text limit, bounded arrays and text, finite ranges/defaults, unique IDs, existing parameter references, panel containment, supported appearance tokens and valid detents. Unknown fields and future versions fail explicitly. Arbitrary code, expressions, remote assets and SDK identifiers inferred from coordinates are not accepted.

Version 1 projects are deterministically migrated to version 2 in memory. Widget bounds, parameters, IDs and style intent are preserved. Missing legacy style, detent, lock and group fields receive defaults. Migration metadata records fromVersion: 1. Local project updates retain the previous raw saved contents as a backup; imports do not overwrite files. Export writes version 2. Versions older than 1 or newer than 2 are unsupported. Fixtures intentionally include v1 files to exercise migration.

Version 2 adds two distinct project-level preset collections:

- Functionality presets store parameter IDs to expose. Applying them retains existing selected controls/styles and allocates missing controls into free space. Missing references, hiding locked controls and insufficient panel space fail transactionally.
- Layout presets store widget arrangement, appearance, panel and theme snapshots. Applying one updates matching currently exposed controls; it does not add functions or restore hidden controls. Locked controls remain unchanged, and any resulting overflow rejects the operation.

Preset names cannot silently overwrite an existing same-type name. Users can delete presets explicitly with undo support. Presets travel with the project JSON; browser-only edits still need Save locally or Export JSON for persistence.

Canvas policy defaults to grid snapping, control alignment snapping, no overlap, an eight-unit gap and no seams. Existing overlapping imports remain readable, but geometry changes must respect the policy; explicitly enabling overlap bypasses that guard. Visual connections reference two distinct existing widget IDs, with an accent and bounded bend amount. They never express parameter mappings. Layout presets include canvas policy and visual connections, remapped to matching exposed controls on application. Runtime manifests optionally include panelStyle and visual connections for drawing only.

This is a limited IR. Plugin class IDs can be unknown (null); raw host ranges do not establish physical units or SDK parameter identity. dataSource is demo-only for the editor. Graph contracts, full widget trees, responsive constraints, verified host registries and native SDK metadata remain future work. Max runtime manifests have an independent runtimeVersion: 1 and intentionally omit editor-only groups, locks and preset libraries.

Host-capture extension: optional parameter resetSource, quantized and enumLabels preserve capture provenance; legacy records default to project-default/unknown/empty. Captured plugin format is unknown, and captured-current explicitly identifies reset baselines. Live capture import does not establish SDK identity, physical units, native plugin compatibility or a running editor connection.

Synthetic graph contracts: optional graphs (maximum eight) declare compressor-transfer or peaking-eq, parameter-role references and sample rate. All referenced parameters must have synthetic provenance. The same contract cannot be attached to host-captured/user-reported parameters. Runtime exports omit graphs with an explicit diagnostic. Future actual-plugin semantics need a different verified contract, not a guessed upgrade of this one.

Native inspection extension: native-inspected parameter evidence means normalized SDK metadata with unverified Live routing; selecting it blocks runtime generation. Native IDs are retained in project IDs such as vst3-4, while full inspection results use a separate validated version-1 contract and SHA-256 binary identity. Only selected controls enter the project, avoiding a 2,748-entry registry in a 256-control IR. A measured fingerprint-bound adapter may establish user-reported Live ranges for specific controls. Generated bundles store previous-on-load reconnect policy; explicit remains backward compatible.

Live session discovery uses a separate catalogVersion 1 contract with instance labels, transient device IDs, bounded diagnostics and existing Live capture records. Catalogs accept no SDK IDs or executable fields. A selected instance becomes a normal captured project with automatic widget placement and previous-on-load target intent. Only project-local exposed indexes identify registry entries; runtime matching still validates actual host names/ranges. Track labels and transient Live IDs are deliberately omitted from the portable project. Current values retain captured-current reset provenance. A catalog is not a persistent target-binding registry.
