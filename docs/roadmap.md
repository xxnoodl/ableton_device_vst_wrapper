# Roadmap and gates

Current next investigation: [single-device plugin hosting](plugin-hosting.md). User-requested research found documented vst~ VST3 hosting and formatted-value output in installed Max. Build an isolated effect-host proof before adopting a new audio path. Prove units/readouts, editor access, state, stable automation, latency and sidechain routing. Keep the working companion runtime as fallback; a saved Rack can package it but does not replace its two internal devices. Manual assembly/binding is not the intended product workflow.

Core host evidence update: session discovery/refresh and generated Color control/reopen passed on Augmented Strings. The horizontal Pro-C 3 wrapper passed two-way control, automatic Set reopen connection when immediately after the plugin, and incoming Threshold automation. These results supersede earlier pending notes below for those specific checks.

1. M0 passed for the Augmented Strings Morph path using the original probe. User-reported host evidence is in progress.md and fixtures/verification.json. Explicit reconnection and automation override behavior are documented.
2. M1 partial: typed v2 IR subset, v1 migration, portable JSON, backup-protected browser storage, isolated static VST3 inventory and host-capture import are implemented. Native SDK inspection and binary fingerprints now work for Windows x64. A new read-only session bridge connects actual exposed Live metadata to checked controls, automatic layout and the generic regular runtime; actual bridge host verification remains pending. Arbitrary native-to-Live routing, automatic Configure and a redistributable audio-plugin DSP fixture remain pending. Static PE fixtures are not plugins.
3. M2 partial: interactive knob designs, detents, function selection, separate presets, multi-selection, resize, align/distribute, group/lock/layers, zoom/pan, properties, themes and undo/redo are implemented. Simulated-DOM/state tests pass; responsive constraints, full accessibility and browser performance remain pending.
4. M3 prototype: reusable native Max source renderer/controller and deterministic source ZIP export are implemented with simulated-host tests. Morph/Motion controls, simultaneous automation, compact presentation and generated shell loading/reopening passed user checks. Capture saving is suspended after crashes; clean-machine portability, gesture/undo and release shell distribution remain pending.
5. M4 partial: synthetic compressor/EQ control-derived previews have numeric tests. Real-plugin EQ semantics, native graphs, measured gain reduction and audio analyzer taps remain unsupported.
6. M5 pending: TypeScript static tooling, desktop packaging, low-end performance, clean-machine compatibility, OS sandbox restrictions and licensing/SDK audits. Network package downloads are blocked. Installed MSVC/CMake were found via vswhere outside PATH; Rust/Cargo remain unavailable.
7. M6 deferred: optional AI and lawful VST2 support. No cloud dependency, telemetry, proprietary assets or external audio bridge introduced.

Do not interpret completed automated tests as universal host compatibility. Continue with independent work where possible; actual new Max runtime behavior requires a licensed host test, and packaged desktop/native SDK work needs the missing toolchain/dependencies.

Current priority: verify the session bridge in Live, then extend dependable discovery/generation/reopening beyond the measured pair. Macro automation remains deferred. Automatic exposure without Configure is still a gap in the intended workflow; do not hide it or silently introduce a different DSP host. The exact-fingerprint native Morph/Motion adapter is a narrow measured path, while the new session path starts from actual exposed parameters instead of guessing SDK mappings.
